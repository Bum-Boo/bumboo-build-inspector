# Security and Privacy Checklist

Use this checklist during post-build security and privacy audits.

| Item | Status | Evidence | Required action | Release blocker? |
|---|---|---|---|---|
| Authentication exists where needed | Unknown |  |  |  |
| Authorization is enforced per route/action | Unknown |  |  |  |
| Session handling is safe | Unknown |  |  |  |
| Passwords are never stored in plaintext | Unknown |  |  |  |
| Input validation exists for user-controlled inputs | Unknown |  |  |  |
| Output encoding protects against XSS | Unknown |  |  |  |
| SQL/NoSQL queries are parameterized | Unknown |  |  |  |
| CSRF protection exists where needed | Unknown |  |  |  |
| SSRF risk is controlled | Unknown |  |  |  |
| Command execution is avoided or constrained | Unknown |  |  |  |
| File uploads are validated and isolated | Unknown |  |  |  |
| CORS is not overly broad | Unknown |  |  |  |
| Rate limiting exists for sensitive endpoints | Unknown |  |  |  |
| Secrets are not hardcoded | Unknown |  |  |  |
| Sensitive data is not logged | Unknown |  |  |  |
| Admin endpoints are protected | Unknown |  |  |  |
| Webhooks are verified | Unknown |  |  |  |
| Payment flows are protected if present | Unknown |  |  |  |
| Privacy policy is present if user data is collected | Unknown |  |  |  |
| Data deletion/export process exists if needed | Unknown |  |  |  |
| AI prompt/output logs are safe if relevant | Unknown |  |  |  |
| Prompt injection surfaces are identified if relevant | Unknown |  |  |  |
